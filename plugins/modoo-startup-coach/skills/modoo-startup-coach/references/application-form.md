# 도전신청서 문항별 가이드 (2026년 2차 기준)

문항 번호·이름·분량은 멘토기관 안내자료와 공개 가이드(k-startup.ai 정리본)를 기준으로 했다. **실제 신청 화면이 우선**이다. 신청 화면은 로그인 후에만 보이므로, 다른 차수라면 신청자에게 화면 캡처를 받아 표를 고친다.

영역 뜻 (2차 개편):
- WHY: 왜 이 아이디어를 생각하게 되었나요?
- WHAT: 어떤 아이디어인가요? (차별: 기존 제품·서비스 대비 차별점, 어떤 문제를 해결하나 / 사업: 어떻게 수익을 창출할 계획인가)
- HOW: 어떻게 실현하고 싶은가요? (계획: 어떻게 사업화할 계획인가 / 보육: 책임멘토를 통해 어떤 도움을 받고 싶은가)
- READY(신설): 아이디어 실현을 위한 준비 과정은 어땠나요? (어떤 역량·강점을 보유했고 어떤 과정을 거쳤나)
- 기창업자(신설): 현재 사업 아이템과 이번 도전 아이디어가 어떻게 다른가
- 재도전(신설): 1기 지원서보다 어떤 점이 더 개선됐나

## 2. 신청서 전체를 꿰는 원칙

1. **한 가지 문제, 한 명의 고객, 한 개의 첫 제품.** 문항마다 다른 고객·다른 문제가 나오면 평가자가 길을 잃는다. Q1의 문장이 모든 문항의 뼈대가 되게 한다.
2. **문제 → 원인 → 해결 → 증거 → 돈 → 계획 → 사람**이 한 줄로 이어지게. 앞 문항의 말을 뒤 문항에서 이어 받는다.
3. **AI·기술이라는 단어보다 흐름.** 경희대 안내 샘플의 원칙: "'AI라는 단어를 많이 쓰는 신청서'가 아니라 문제, 데이터, 기술, 검증, 사업화가 하나의 흐름으로 연결되게."
4. **1R은 아이디어 심사다.** 시제품·MVP가 없어도 신청할 수 있다. 대신 "1R 기간(약 2~3개월)에 무엇을 확인할지"가 분명해야 한다. 2R에서 시제품·MVP를 만든다.
5. **사실과 계획을 구분한다.** 이미 한 것(완료) / 하고 있는 것(진행) / 할 것(계획) / 모르는 것(가설)을 섞지 않는다.
6. **근거는 짧게 출처와 함께.** 본문 안에 (기관명, 자료명, 연도)를 짧게 붙인다. 최근 2~3년 자료를 쓴다.
7. **트랙의 말로 쓴다.** 일반/기술 = 차별성·효과성·확장성. 로컬 = 지역 자원(무엇이, 어디에, 왜 그 지역에서만), 창의성, 지역적 가치(지역 주민·생산자·상권에 무엇이 남나).

## 3. 문항별 가이드

각 문항: 평가자가 찾는 것 / 담을 것(순서) / 좋은 신호 / 나쁜 신호 / 설계도에 넣을 질문.

### Q1 아이디어 한 줄 소개

- **평가자가 찾는 것**: 3초 안에 "누구의 어떤 불편을 무엇으로 어떻게 푸는지"가 보이는가. 차별성·효과성(로컬: 창의성·지역적 가치)의 단서가 있는가.
- **담을 것**: [대상 고객/상황] + [핵심 방식(무엇을 이용해 어떻게)] + [결과·가치] (+ 첫 검증 대상, 로컬은 지역 자원).
- 틀: "○○ 때문에 △△를 겪는 □□을 위해, ◇◇로 ▽▽하는 서비스(제품)입니다."
- 안내 샘플 형태(뼈대만): "[원료·공정 데이터]를 AI가 학습하여 [목표 결과]에 맞는 [조건]을 추천하고, [첫 실증 제품]으로 검증하는 [정체성] 솔루션".
- **좋은 신호**: 고객이 보인다, 동사가 분명하다, 과장어 없음, 60~120자.
- **나쁜 신호**: 서비스 이름만 있음("○○ 플랫폼"), "혁신적인 AI 플랫폼", 고객 없음, 기능 나열.

### Q2 아이디어 배경 (WHY, 2,000자)

- **평가자가 찾는 것**: 실제로 존재하는 문제인가, 신청자가 그 문제를 직접 겪거나 가까이서 봤는가(도전의 진정성), 지금 풀어야 할 이유가 있는가.
- **담을 것(순서)**:
  1. 문제를 처음 알게 된 **장면** (언제, 어디서, 누가, 무엇을 겪었나 — 신청자 경험)
  2. 사람들이 지금 그 문제를 **어떻게 버티고 있나** (현재 방법과 그 비용·불편)
  3. 문제의 **크기** (출처 있는 최신 통계 1~2개, 또는 직접 확인한 사실: 몇 명에게 물어 몇 명이 그렇다고 했나)
  4. **왜 지금**인가 (기술·제도·소비 변화)
  5. **왜 나**인가 (경험·전공·현장 접근성 — 한두 문장, 상세는 Q8)
- **좋은 신호**: 구체적인 장면과 숫자, 인터뷰·현장 확인, 출처 표기, 문제를 과장하지 않음. 안내 샘플은 "사과 생산량 감소를 근거로 비상품 사과 규모를 임의로 추정하지 않고, 1R에서 실제 농가 인터뷰로 확인하겠다"처럼 **모르는 것을 모른다고** 쓰고 확인 계획을 붙였다.
- **나쁜 신호**: "현대 사회는 빠르게 변화하고…"로 시작하는 일반론, 출처 없는 통계·오래된 데이터, 남의 문제를 들은 이야기로만, 제도·정책에 대한 불만(심사 제외 사유), 시장 규모만 길게.

### Q3-1 차별점과 문제해결 (WHAT-차별, 2,000자)

- **평가자가 찾는 것**: 기존 제품·서비스(대체재 포함)와 무엇이 다른가, 그 차이가 문제를 실제로 푸는가, 접근 방식이 새로운가.
- **담을 것(순서)**:
  1. 핵심 차별점 한 문장 ("○○ 자체가 아니라 △△가 핵심이다")
  2. 현재 대안 2~3개(경쟁 서비스, 사람들이 쓰는 방법, 수작업)의 **한계**
  3. 내 방식의 **작동 원리** (단계: 입력 → 처리 → 결과. 기술이면 무엇을 입력받아 무엇을 예측·추천·제공하는지 한 문장으로 설명 가능해야)
  4. 그래서 고객에게 생기는 **효과** (실증 전이면 '목표'로)
  5. 쉽게 따라 하기 어려운 이유 (데이터·원물·네트워크·노하우·현장 접근)
- 비교는 표 대신 문장으로 써도 되지만, "기존 → 우리" 짝을 분명히.
- **좋은 신호**: 대체재까지 고려, 기술을 쉬운 말로, 한계도 인정(예: "이미지 분석만으로 식품 안전을 판단하지 않는다").
- **나쁜 신호**: "경쟁사 없음", "국내 최초·유일", 기능 나열, 실증 전 확정 수치("정확도 95%"), 경쟁사 이름만 나열.

### Q3-2 수익창출 계획 (WHAT-사업, 2,000자)

- **평가자가 찾는 것**: 누가, 무엇에, 어떻게 돈을 내는가가 현실적인가. 단계별로 커지는 길이 보이는가.
- **담을 것(순서)**:
  1. 첫 수익: **돈을 내는 사람**(사용자와 다를 수 있음), 상품, 가격 가설, 판매 채널
  2. 단계별 수익모델 (1단계 판매·서비스 → 2단계 B2B·기관 → 3단계 구독·플랫폼 등), 단계마다 고객과 검증 지표
  3. 가격·원가 가설과 확인 방법 (아직 모르면 '가설'이라고 밝히고, 어떻게 확인할지)
  4. 수익에 영향을 주는 **법·제도 조건** (예: 주류 제조·통신판매, 식품 영업신고, 의료기기, 개인정보)
- **좋은 신호**: 지불 주체가 분명, 과금 방식 구체(월 구독, 건당, 기기 판매, 기관 계약), 초기에는 작게 시작, 규제 확인 계획.
- **나쁜 신호**: "광고 수익·수수료·구독 등 다양한 수익모델", 근거 없는 매출 전망, 시장 점유율 몇 %만 제시, 무료로 모으고 나중에 돈 번다는 말만.

### Q4-1 사업화 계획 (HOW-계획, 2,000자)

- **평가자가 찾는 것**: 단계가 현실적이고 신청자의 시간·역량으로 할 수 있는 규모인가. 단계마다 완료 기준이 있는가.
- **담을 것(순서)**:
  1. 전체 단계 한 줄 (예: 문제 검증 → 데이터 확보 → 기초 모델 → 시제품 → 판매 검증 → 확장)
  2. **1R 기간(약 2~3개월)에 할 일**과 완료 기준 (몇 명 인터뷰, 몇 건 데이터, 시제품 몇 종 등), 창업활동자금 200만원·AI 솔루션 100만원을 무엇에 쓸지
  3. 2R(시제품·MVP) 목표, 3R 이후 방향
  4. 확인할 법·인허가·인증과 협력 파트너(확정 / 협의 중 / 예정 구분)
- 안내 샘플의 1R 목표 표 예: 농가 인터뷰 10곳 이상 / 이미지 데이터 500건 / 원료 계측 100건 / 테스트 배치 20~30 / 시제품 2~3종 → MVP 1종 / 소비자 테스트 100명 / 판매처 인터뷰 20곳 / 기초모델 1식. (교육용 예시. 신청자 역량에 맞게 줄여야 한다)
- **좋은 신호**: 숫자로 된 완료 기준, 작게 시작, 순서가 맞음(검증 → 제작 → 판매), 1R 결과가 2R 계획의 근거가 됨.
- **나쁜 신호**: "1년 내 전국 확대, 3년 내 해외 진출", 완료 기준 없음, 혼자 하기 불가능한 규모, 확정되지 않은 협약을 확정처럼.

### Q4-2 책임멘토에게 받고 싶은 도움 (HOW-보육, 2,000자)

- **평가자(책임멘토 본인)가 찾는 것**: 이 사람을 멘토링하면 성장할까, 무엇을 모르는지 아는가, 우리 기관이 도울 수 있는가.
- **담을 것**: 모르는 것·막힌 것을 **구체적 질문 3~5개**로 (예: "주류 제조 면허 없이 위탁 생산으로 첫 판매가 가능한 구조인지", "1R 데이터 수집 설계에서 표본 수를 어떻게 정해야 하는지"), 질문마다 왜 필요한지와 1R 계획의 어느 단계와 연결되는지, 고른 멘토기관의 강점(전문 분야·네트워크)과의 연결.
- **좋은 신호**: 멘토가 바로 답할 수 있는 질문, 1R 계획과 연결, 기관 특성 이해.
- **나쁜 신호**: "전반적인 도움", "투자 유치 연결", "자금 지원" 같은 막연한 요청, 멘토에게 일을 대신 맡기는 요청.

### Q5 소개 영상 (선택, 30~60초 URL)

- 말로 설명하기 어려운 **사용 장면·문제 장면**을 보여 준다. 안내 샘플 구성: 0~7초 질문으로 시작 → 8~17초 문제 장면 → 18~30초 해결 방식 → 31~43초 핵심 원리 → 44~55초 첫 결과물·확장 → 56~60초 한 줄 마무리.
- 얼굴·목소리는 신청자 본인이 나오는 편이 진정성에 좋다. 공개 범위(특허 공지 문제)를 확인한다.

### Q6 사업 분야

- 아이디어의 **핵심 가치에 가장 가까운** 분야를 고른다. 융합형이면 본문(Q3-1)에 융합 내용을 쓴다. 경쟁률만 보고 바꾸지 않는다.

### Q7 창업 여부 / Q7-1 기존 사업과 이번 아이디어의 차이

- 예비창업자: 현재 상태와 창업(사업자등록) 계획 시점, 필요한 인허가를 한두 문장으로.
- 기창업자(Q7-1): 기존 사업의 업종(세세분류)·고객·제품과 이번 아이디어의 **업종·고객·제품 차이**를 나란히. 이종창업으로 새 사업자를 낼 계획. 기존 사업에서 얻은 자산(고객·데이터·현장)은 강점으로 쓰되 "같은 사업의 확장"으로 읽히지 않게.

### Q8 본인 역량 (READY)

- **평가자가 찾는 것**: 이 아이디어를 실행할 사람인가, 준비 과정이 있었나(창업 의지·준비도).
- **담을 것**: 아이디어 실행에 **직접 쓰이는** 경험·전공·자격·현장 접근성만, 지금까지 해 온 준비(탐색·고민·학습·인터뷰·시도), 부족한 역량과 보완 방법(팀·외부 협력·멘토링), 1R에서 스스로 답하고 싶은 질문.
- 안내 샘플의 좋은 태도: "AI 개발자와 양조 전문가 역할을 모두 할 수 있다고 과장하지 않는다. 내 역할은 현장 문제를 데이터로 정의하고 결과에 따라 제품과 기술을 빠르게 수정하는 것."
- **나쁜 신호**: 이력서 나열, 아이디어와 무관한 경력, 모든 걸 혼자 할 수 있다는 과장.

### Q9 팀원 정보 (선택)

- **실제 있는 사람만** 쓴다. 없으면 "필요 역할 / 담당 업무 / 현재 상태(확정·외부 협업 확보 예정·필요 시 외부 협업)" 표로 필요 역량과 확보 방식을 밝힌다. 존재하지 않는 팀원·전문가를 확정된 것처럼 쓰지 않는다.

### Q10 아이디어 자랑 (선택, 홈페이지 공개)

- 공개돼도 되는 내용만. 핵심 노하우·특허 출원 전 기술 세부는 빼고, 문제와 가치를 쉬운 말로.

### 재도전: 1기와 달라진 점 (재도전자, 가점 최대 3점)

- **평가자가 찾는 것**: 1기 아이디어의 한계를 스스로 알았는가, 무엇을 확인·학습했는가, 실제로 무엇을 바꿨는가.
- **담을 것(순서)**: 1기 아이디어 요약 → 1기 이후 확인한 한계(무엇을 해 보고 무엇을 알았나) → 바꾼 점(고객, 문제 정의, 구조, 수익모델, 검증 방법) → 바꾼 근거 → 그래서 2기 아이디어가 무엇이 되었나.
- 안내 샘플 흐름: "1기는 '지역 사과로 과실주 개발'이라는 제품 중심 → 제품 하나가 성공해도 다음 개발에 시행착오가 반복되는 한계 확인 → 2기는 원료·공정·품질 데이터를 핵심 자산으로 바꿔 '제조 조건을 추천하는 구조'로 고도화 → 1기는 '새 제품 만들기', 2기는 '시행착오를 데이터로 줄이는 기술창업'".
- 1차 때 가입한 수단으로 신청해야 가점이 적용된다.

## 4. 작성 설계도 틀 (모드 ②에서 문항마다 채운다)

| 칸 | 내용 |
|---|---|

## 5. 글자 수 메모

- 2,000자 제한은 신청 화면 기준이다. 공백 포함으로 세는지 화면에서 확인한다(`check_draft.py`는 둘 다 보여 준다).
- 플랫폼에 붙여 넣은 뒤 화면 글자 수를 다시 확인한다. 줄바꿈·특수문자·표가 다르게 세어질 수 있다.
- 너무 짧은 답(1~2줄)은 "성의 없음"으로 읽힌다. 핵심 문항은 최소 800자 이상 권장.
